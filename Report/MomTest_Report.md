## 인터뷰 전문

### Q1. UnitConverter 실습 전, 단위가 섞인 값을 다룬 가장 최근 순간

**답변:** 미국과 한국 단위가 달라 영어 문서를 확인할 때 주로 feet를 meter로 암산해 변환하는데 어려움이 있음. meter·feet·yard 차이도 정확히 모름.

*(솔루션 언급 — "미터로 자동 변환" → 그건 나중)*

### Q2. 막혔을 때 실제로 한 일

**답변:** 인터넷에서 단위 변환기를 검색해서 변환함.

### Q3. 막힘부터 결과 확인까지 소요 시간

**답변:** 대략 10분 이상.

### Q4. 10분 동안 실제로 한 일

**답변:** 인터넷 포털 → 단위 변환기 검색 → UI가 쉽고 간단한 변환기 탐색.

### Q5. 10분이 넘게 걸린 이유

**답변:** 포털 열기, 검색, UI가 쉽고 간단한 변환기를 찾아야 했음.

### Q6. UI가 마음에 안 들어 포기한 사이트

**답변:**
- 영어로 복잡하게 되어 있고 입력 UI가 불편한 사이트
- **직관적(선호):** 카테고리·입력·출력·공식이 한 화면에 보이는 UI
- **비직관적(포기):** 길이 등 카테고리를 한 단계 더 선택해야 하는 UI — 바로 이용 불가

### Q7. 비직관적 사이트를 만났을 때 행동

**답변:** 다른 것을 찾으러 나감.

### Q8. 직관적인 변환기를 찾을 때까지 연 사이트 수

**답변:** 4~5개. UI가 깔끔하고 복잡하지 않으며 직관적인 사이트를 찾음.

→ 솔루션(프로그램·자동 변환)이 문제 정의에 섞여 있음.

### 2. 진짜 문제 (한 문장)

영어 문서를 읽다가 feet·yard 숫자를 meter 감각으로 바로 판단하지 못할 때, **문서 읽기가 끊기고** 변환기를 찾·고르는 데 **10분 이상·사이트 4~5개**를 쓰며 **직관적인 UI를 골라야만** 다음으로 넘어갈 수 있다.

### 3. Mom Test 증거 (인터뷰 인용)

1. "막혔던 순간에 **인터넷에서 단위 변환기를 검색**해서 변환을 했었어."
2. "**대략 10분 이상**이 걸렸던거 같아."
3. "**4~5개는 열어본거 같아.** 우선 UI가 깔끔하고 복잡하지 않고 직관적인 사이트를 찾아봤었어."
